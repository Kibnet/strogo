# Происхождение публичной версии

Strogo впервые опубликован 2026-09-06 как самостоятельный снимок локального исследовательского проекта `agent-language-kernel-v0` на commit `ea6c0b6a491745c204dcb5ee7e4df8cff0966ce6`.

Исходная локальная история не переписана. У публичного репозитория новая история; прежние commit/blob IDs остаются идентификаторами происхождения и не являются ссылками на commits этого репозитория.

## Что перенесено

Исходники, существующие проверки, fixtures, формальная модель, runtime adapter, закреплённые зависимости и исполняемые scripts перенесены без изменения байтов. [Опись SHA-256](publication-source.json) содержит 69 файлов и исходную ревизию.

Добавлены самостоятельные README, описание цели и переносимые инструкции. Исходное руководство Reserve сохранено в [docs/reserve-v0.md](reserve-v0.md). [Журнал E04](e04-knowledge-log.md) опубликован как исторический снимок знаний.

Личные пути заменены маркерами `<original-checkout>`, `<private-knowledge-base>` и `<user-home>`. Идентификаторы частных сессий удалены. Исторические технические ошибки и отрицательные результаты сохранены. Полные журналы сессий, локальные базы данных, бинарники инструментов и остальные материалы личной базы знаний не входят в публикацию.

## Как читать исторические результаты

Файлы `artifacts/`, `REPORT.md` и спецификации описывают прежние эксперименты. Числа 29 сценариев / 10 904 проверки v0 и 141 проверка E04 относятся к зафиксированным локальным запускам. Их наличие в GitHub само по себе не означает нового запуска или прохождения GitHub Actions.

Публикационные копии некоторых документов и JSON очищены от личных путей. Поэтому их байтовые hashes могут отличаться от исходных файлов; перечень изменённых исторических файлов находится в описи. Прежние receipts, tool paths, runtime hashes и source manifests сохранены для анализа и не являются переносимыми допусками к исполнению. Для своего checkout необходимо заново выполнить `contract` и `compile` по руководству E04.

Утверждённые commit/blob IDs внутри runtime и approval сохраняют связь с исходной SPEC. Публикационная копия SPEC с заменёнными путями не объявляется исходным blob с тем же hash.

`tools/Check-KnowledgeSync.ps1` сохранён без изменения как инструмент исходного workflow. Проверка старого `knowledge-sync.json` требует исходных проектной истории и базы знаний; публичного checkout для неё недостаточно. Это ограничение исторического provenance, а не проверка работоспособности публичного runtime.

## Статус

Реализованы два ограниченных экспериментальных профиля. Универсальность языка, сокращение полного цикла работы агента и сопоставимость производительности программ ещё не доказаны. SPEC v0.1 остаётся предложением, не утверждённым и не реализованным этапом.

Лицензия для проекта пока не выбрана; этот snapshot не добавляет лицензионного разрешения от имени владельца.
